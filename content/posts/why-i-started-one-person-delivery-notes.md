过去十一年，我主要做后端与分布式系统；后来有四年半时间，我带着数据分析团队做模型服务与 LLM 应用。真正让我开始重新思考「一个人能交付多少软件」的，是最近两年把 AI agent 放进日常研发流程之后的体验：需求拆解、代码生成、测试补齐、部署检查，很多过去必须由团队并行完成的工作，开始可以被一个人编排。

但「一个人 + 多 agent」并不是把任务丢给模型就结束了。它更像设计一条流水线：哪些环节必须由人判断，哪些环节可以自动执行，失败时如何回滚，证据如何保留。这些问题没有现成答案，只能在实际交付里一次次试。

「一人交付笔记」就是为这件事开的公开记录。我会写下完整的项目复盘、技术取舍、失败路径和可复用的工作流，而不是只展示结果。读者如果也在独立开发或经营一人公司，希望这些记录能帮你少走一点弯路。

这个站点本身也是一次实验：Markdown 写作为内容源，Git 管理版本，静态生成后部署到 Cloudflare Pages。正文以服务端生成的 HTML 呈现，不依赖 JavaScript 也能完整阅读，方便读者、搜索引擎与 AI agent 获取内容。

第一篇先写到这里。接下来，我会从一次真实的多租户 SaaS 交付开始，拆解一个人如何借助多 agent 流水线完成设计、实现、测试与上线。

## 这里会写什么

- 一人公司的软件交付方法：范围控制、架构取舍、质量门槛。
- AI agent 流水线的实际用法：任务编排、上下文管理、验证与回滚。
- 真实项目的复盘：指标、失败、成本与时间线，涉及客户信息时统一脱敏。

## 这里不会写什么

不写无法验证的成功学，不暴露客户名称、儿童信息、手机号或任何密钥，也不把 AI 生成的内容当作未经审查的事实。每一篇都尽量给出可复核的过程与证据。
