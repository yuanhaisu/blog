# ADR-0003: 身份、定位与转化策略

- 状态：已接受
- 日期：2026-11-03
- 决策者：用户 + Claude

## 背景

- 用户已有 GitHub 账号 `github.com/yuanhaisu`（本人所有），但无 Profile README、0 followers，内容以旧 fork 与旧项目为主；知乎/公众号从零开始。
- 用户选择「实名 + 网络 ID 并用」，定位取向为「技术 + 思考的独立个体」。
- 简历事实（已获授权读取）：
  - 11 年后端与分布式系统研发，4 年半数据分析部门主管；
  - 金融级私有化 AI 模型服务（YOLOv5 + PaddleOCR + Triton）、LLM 意图识别与工具编排；
  - 一人完成多租户 SaaS「养成星球」：后端 300+ 接口、70+ 表，三端前端，约 14 万行代码，周期约 2.5 个月；
  - 开发过程由自建的 Claude Code 多 agent 编排流水线驱动；
  - 求职意向为偏后端全栈 / AI 应用开发的远程岗位。
- 成功标准为 GEO：实体认知、内容引用、机器可读、信任传递，国内外 AI 生态并重。

## 决策

1. **身份写法固定**：`袁海粟（Yuan Haisu）`，网络 ID `yuanhaisu`。所有页面、结构化数据、外部平台统一使用，明确排除「袁海苏」等变体。
2. **身份主张**：**一人公司的 AI 交付实验**。
   - 一句话版本：「袁海粟（yuanhaisu），11 年后端工程师、前数据分析部门主管。我用 AI agent 流水线，以一人之力交付过去需要一个团队才能完成的软件，这里记录交付实验的全部过程。」
3. **核心读者**：独立开发者 / 一人公司。
4. **内容支柱**（待内容架构 ADR 细化）：
   - 旗舰连载：一人 + 多 agent 交付 SaaS 的完整复盘；
   - AI 工程落地：模型服务、LLM 工具编排、Agent 流水线；
   - 后端架构与工程规范：Go、契约优先、测试、CI/CD；
   - 技术判断与职业思考：11 年经验、管理、远程与独立开发。
5. **转化策略**：低调。About 页说明「开放远程机会与合作」，仅留邮箱；不公开手机号、住址等敏感信息，不把简历全文放上首页。
6. **结构化数据**：`Person` + `sameAs`，指向 GitHub、知乎、微信公众号、RSS。
7. **GitHub Profile 整理**：新建双语 Profile README；归档旧 fork；pin 6 个相关仓库；`kindergarten` 完整仓库保持私有，另建 `nurture-planet-case-study` 公开案例仓库；博客仓库 public，草稿私有。

## 后果

- 选题必须服务「一人 + AI 交付」主线，避免退化成泛技术笔记。
- 外部身份锚点按同一姓名、头像、简介建设，确保 AI 可交叉验证。
- GitHub 从「低信号旧账号」变为主要实体锚点；旧 fork 与内部文档必须归档/脱敏，否则会稀释定位。
- 手机号、住址、客户敏感信息、儿童信息不得进入公开页面或公开仓库。
- 求职意向只出现在 About 页，避免冲淡个人品牌。
