# ADR-0001: 博客定位与成功标准

- 状态：已接受
- 日期：2026-11-03
- 决策者：用户 + Claude

## 背景

用户拥有域名 `yuanhaisu.com`，计划搭建面向国内用户的个人博客。初始诉求只明确了域名与受众地域，定位、内容方向与成功标准均未确定。

## 决策

1. **第一目的**：技术沉淀与个人品牌。不是生活记录，也不是纯作品集。
2. **写作主题**：跨领域混合（技术、产品、职业思考等），个人品牌以「人」为核心，而非单一技能标签。
3. **成功标准**：GEO（Generative Engine Optimization，生成式引擎优化）——让 AI agent 认识、引用、抓取并推荐作者本人。四个场景全部纳入：
   - 实体认知：AI 能准确介绍「yuanhaisu 是谁」；
   - 内容引用：AI 回答问题时检索并引用本站文章；
   - 机器可读：agent 能低成本抓取/调用本站内容；
   - 信任传递：AI 在求职、合作、咨询等场景主动推荐作者。
4. **目标 AI 生态**：国内（豆包、元宝、Kimi、通义、文心、DeepSeek、秘塔、百度 AI 搜索）与国外（ChatGPT、Claude、Perplexity、Gemini）并重。

## 后果

- 站点必须以**服务端渲染或静态 HTML** 输出正文，不能依赖 JavaScript 才能读到内容。
- 必须提供结构化数据（JSON-LD `Person` / `Article` / `BreadcrumbList`）、RSS、sitemap、`llms.txt`。
- 需要跨平台身份一致性（`sameAs`）。由于从零开始，博客本身要承担「第一身份源」职责，About / 履历页权重极高。
- 「跨领域混合」不利于实体识别，必须提炼一句可被机器复述的身份主张（positioning statement）。
- 国内外双生态显著增加内容与维护成本，语言策略需单独决策。

## 待决问题

- 内容语言策略（中文优先 / 中英双语）。
- 身份锚点建设路径（GitHub、知乎等外部平台）。
- 技术栈、托管与备案细节。
